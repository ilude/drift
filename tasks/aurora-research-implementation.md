# Aurora 4X Research → Drift Implementation Notes

**Primary source:** https://erikevenson.github.io/aurora-manual/

## What Aurora Does

Aurora's research system organizes technology into nine categories (Power & Propulsion, Sensors, Direct Fire, Missiles, Construction, Logistics, Defensive Systems, Biology/Genetics, Ground Combat). Research Points (RP) are generated by ground-based labs — each produces 200 RP/year baseline, scaled by scientists' specialization bonuses (0–50%, with 4× multiplier when in-specialty), research rate tech level (240–1500 RP/year), and scientist administration caps. Technologies escalate exponentially in cost (500 RP to 5M RP+), with prerequisites forming branching chains. Scientists are named commanders with primary/secondary specializations; they cap the number of labs they can effectively oversee. Ancient constructs found during exploration count as field-specific research labs. Prototype system allows testing components before research commitment.

## Drift Design Constraints

- **Depth without complexity:** Aurora's fidelity yes, Aurora's micromanagement no
- **System chaining:** Every mechanic must link to 2–3 others or it's patchwork
- **Rate modifier pattern:** `effectiveRate = baseRate * quality / hardnessMultiplier`
- **Colony structure (existing):** `labs` (ColonyInstallations.lab), `researchPoints` field, constructionProjects, `ColonyResearchProject` with techId, assignedLabs, progressRp, leadScientistId, difficulty
- **Research structure (existing):** `researchedTechs` Set in AppState; Scientists have `categoryBonuses`, `adminCap`, `activeProjectTechId`, `projectQueue`
- **20 techs in RESEARCH_DEFS** (2026-03-26) — 5 categories with 4 techs each: Survey (survey-automation, advanced-telemetry, predictive-analysis, deep-scan-array), Industry (mining-drills, fabrication-methods, advanced-metallurgy, nano-manufacturing), Logistics (maintenance-doctrine, supply-optimization, fleet-logistics, rapid-refit), Research (lab-instrumentation, sensor-theory, applied-physics, unified-field-theory), Biology (basic-hydroponics, genetic-medicine, closed-cycle-life-support, xenobiology) ✓
- **Prerequisites implemented** (2026-03-26) — `ResearchDefinition` now includes `prerequisites: string[]`; `canStartProject()` validates prereqs ✓
- **Global research management screen** (2026-03-26) — `src/ui/research-viewer.ts` (popout, popout-style with category/state filters, scientist queue management, project progress tracking) ✓
- **Still pending:** Tech effects actually applying to game systems (engine gates, survey/industry bonuses); eureka-style survey breakthroughs; scientist generation at academies

## Drift Implementation Sketches

### 1. Expand the Tech Tree to ~15–20 Techs

**Current state:** 5 hardcoded techs in RESEARCH_DEFS.

**What to add:** TechDefinition interface with prerequisites, formalize into branching chains across 4 categories.

```typescript
interface TechDefinition extends ResearchDefinition {
  prerequisites: string[];       // techIds that must be in researchedTechs first
  effectBonusKey?: string;       // which getEmpireTechBonuses() key this unlocks
  revealedAt?: number | null;    // simDay it appears (null = always visible)
  eurekaSourceTechs?: string[];  // unlocked partially by survey discoveries
}
```

**Proposed tech tree (~20 techs, 5 categories):**

| Category | Tier 1 (120 RP) | Tier 2 (250 RP) | Tier 3 (500 RP) | Tier 4 (1000 RP) |
|----------|-----------------|-----------------|-----------------|-------------------|
| Survey | Survey Automation | Advanced Telemetry | Predictive Analysis | Deep Scan Array |
| Industry | Mining Drills | Fabrication Methods | Advanced Metallurgy | Nano-Manufacturing |
| Logistics | Maintenance Doctrine | Supply Optimization | Fleet Logistics | Rapid Refit |
| Research | Lab Instrumentation | Sensor Theory | Applied Physics | Unified Field Theory |
| Biology | Basic Hydroponics | Genetic Medicine | Xenobiology | Terraforming |

**Biology/Genetics gates:** food production (colony population stability), health and life expectancy (population growth, scientist/officer career length), ship life support improvements (supply endurance), and terraforming (long-duration habitability modification of colony bodies). Implementation of these downstream systems is deferred — the category exists in the tree to reserve the design space.

**Why:** Matches Aurora's branching structure without 100+ technologies. Small chains create visible progression goals.

### 2. Tech Prerequisites Check

**Gap:** `canStartProject()` doesn't verify prerequisites.

**What to add:**
```typescript
export function canStartProject(techId: string): boolean {
  const tech = RESEARCH_DEFS[techId] as TechDefinition;
  if (!tech) return false;
  for (const prereq of tech.prerequisites ?? []) {
    if (!state.researchedTechs.has(prereq)) return false;
  }
  return true;
}
```

Block queueing if prerequisite unmet. Show in UI: "Requires: [Missing Prereq]" in gray on locked techs.

### 3. In-Specialty Bonus (Simplified)

**Aurora gap:** 4× in-specialty multiplier is too harsh for small empires. Drift's existing 1 + bonus structure is sufficient.

**Drift tweak:** If scientist assigned off-category, apply 0.5× penalty. Generalists work; specialists shine.

```typescript
function getScientistBonus(scientist: Scientist, categoryId: string): number {
  const raw = scientist.categoryBonuses[categoryId] ?? 0;
  const isPrimary = categoryId === scientist.primarySpecialization;
  return isPrimary ? (1 + raw) : (1 + raw) * 0.5;
}
```

**Anti-pattern to avoid:** Don't implement the full 4× penalty — leads to permanent reassignment paralysis.

### 4. Research Facility Scaling (via Tech Bonuses, not Lab Tiers)

**Aurora pattern:** "Research Rate" tech progression (240 → 1500 RP/year). Ancient constructs count as equivalent labs.

**Drift decision:** Do NOT add explicit "lab tiers." Instead, let techs scale baseline lab output:
- "lab-instrumentation" → +20% RP/day per lab
- "advanced-physics" → +30% RP/day per lab

Computed via `getEmpireTechBonuses()` applying to `BASE_RESEARCH_RATE` in the research tick.

**Why:** Keeps labs simple. Tech tree drives lab value. Minimal new UI.

### 5. Eureka Survey Breakthroughs

**Aurora parallel:** Prototype system — test component before committing to full research.

**Drift approach:** Survey completion on specific body types grants partial RP toward thematically linked techs.

```typescript
// In TechDefinition
eurekaSourceTechs: string[];
// e.g., "advanced-telemetry" has eurekaSourceTechs: ["survey-3", "moon-survey"]

// On survey level-up in commands.ts:
function checkEurekaBreakthroughs(body: BodyEntry): void {
  for (const [techId, tech] of Object.entries(RESEARCH_DEFS)) {
    if (tech.eurekaSourceTechs?.includes(body.bodyType)) {
      const partial = tech.costRp * 0.2;
      // Inject 20% progress into that tech if queued or add to discovery pool
      addEurekaRp(techId, partial);
    }
  }
}
```

Log event: "Breakthrough: Advanced Telemetry from deep survey of [Body]"

**Why:** Ties survey (exploration core) to research. Reduces grind. Rewards exploration with tangible mechanical benefit.

### 6. Scientist Generation at Academies

**Gap:** `seedInitialScientistsAtColony()` runs once; no ongoing scientist production.

**What to add:** Academy construction completion triggers scientist spawn events.

```typescript
// On construction project completion (colonies.ts):
if (project.installationId === "academy") {
  scheduleScientistGeneration(colony.bodyName, 30); // one scientist after 30 days
}

// Rate: 1 scientist per 2 academies per 30 sim-days
function tickAcademyScientistProduction(colony: ColonyState, dt: number): void {
  const rate = Math.floor(colony.installations.academy / 2) * 0.033; // per day
  colony.pendingScientistProgress = (colony.pendingScientistProgress ?? 0) + rate * dt;
  if (colony.pendingScientistProgress >= 1) {
    colony.pendingScientistProgress -= 1;
    spawnScientistAtColony(colony.bodyName);
  }
}
```

**Cap:** Soft cap at 1 scientist per 1,000 population to prevent infinite growth.

### 7. Engine Tech Gates (Research → Ship Capability)

**What's missing:** Engine tiers in `ship-physics.ts` are all available from game start.

**Drift approach:** Gate improved/advanced/extreme engines behind Power & Propulsion research.

```typescript
// Add to RESEARCH_DEFS:
"improved-propulsion": {
  name: "Improved Propulsion",
  category: "logistics",
  prerequisites: ["maintenance-doctrine"],
  costRp: 250,
  // Effect: unlocks engine tier "improved"
},

// In createShip() or ship designer:
const allowedEngines = ENGINE_TYPES.filter(e =>
  e.requiredTech == null || state.researchedTechs.has(e.requiredTech)
);
```

**Why:** Creates clear reason to research. Ties ship progression to tech tree. Avoids explosion of engine variants.

## Anti-patterns to Avoid

- **4× in-specialty multiplier** — Leads to permanent reassignment paralysis. Use 0.5× off-category penalty at most.
- **Lab tier upgrades** — "Lab v1/v2/v3" with separate techs. Just use tech bonuses to scale base rate.
- **Unlimited scientist spawning** — Rate-gate by population and academy count.
- **Silent tech locks** — Always show prerequisites before queueing. Never silently fail.
- **Cross-colony research pooling** — Keep research strictly local to one colony per project.
- **Prototype system** — Don't implement Aurora's design-then-research-then-build. Single design phase is tighter.
- **Research Rate in Biology/Genetics** — Keep research-rate tech in the Research category, discoverable.
